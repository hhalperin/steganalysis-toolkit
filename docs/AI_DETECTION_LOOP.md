# AI Detection Loop: Multi-Agent Workflow

A prompt-hook workflow that uses three agent roles to identify AI-generated tells in an image, plan fixes, review the plan, get feedback from the identifier, improve the plan, implement it, and rerun until the image no longer reads as clearly AI-generated.

## Roles and handoffs

| Role | Responsibility | Input | Output |
|------|----------------|--------|--------|
| **Identifier (Agent 1)** | Point out every part of the image that makes it look AI-generated | Image | Structured findings list |
| **Planner (Agent 2)** | Propose what would make those parts seem non-AI | Findings (+ optional image) | Structured plan |
| **Reviewer (Agent 3)** | Review plan and ask Identifier if fixes would help | Plan | Questions for Identifier |
| **Identifier (feedback)** | Answer: would these fixes help? | Image + questions | Structured feedback |
| **Planner (improve)** | Revise plan using feedback | Plan + feedback | Improved plan |
| **Implementer** | Apply edits to the image | Improved plan + current image | New image (or edit spec) |
| **Loop** | Rerun Identifier on new image; if still AI-tells → repeat from Planner | New image | Done when Identifier finds no/nominal tells |

---

## State directory

All handoff files live under **`assets/processing/ai-loop/`** (create if missing):

- `findings.json` — Identifier output (round N)
- `plan.json` — Planner output
- `review.json` — Reviewer output (questions)
- `feedback.json` — Identifier feedback answers
- `improved_plan.json` — Revised plan
- `current.png` — Current image (copy of input or last edited result)
- `edited_1.png`, `edited_2.png`, … — Edited images per round
- `edit_spec.md` — Optional: human/script-readable edit instructions from improved plan
- **`loop_state.json`** — Round counter and cap: `round`, `max_rounds` (default 10), `completed`, `updated_at`
- **`loop.log`** — Structured JSONL log of every phase (init, identifier, next, implement, stopped) for observability

## Max rounds and loop cap

The loop does **not** run forever. It is capped at **10 rounds** by default. After 10 full cycles (Identifier → … → Implement), the loop stops: `loop_state.json` is set to `completed: true` and no further rounds are run. You can see the current round and cap in every `ai-loop next` and `ai-loop implement` output, and in `loop.log`.

## Logging (observability)

**Two outputs:**

1. **Terminal (stdout)** — Clean, context-engineered lines for agents: `ai-loop round=N phase=... key=val ...` (no timestamp, no fluff). Same prefix and key=value style so an agent can read the stream as a cohesive system record. Example: `ai-loop round=1 phase=init image_path=photo.png max_rounds=10`.

2. **File `assets/processing/ai-loop/loop.log`** — Full JSONL (one JSON object per line) for machine parsing. Each entry includes `ts`, `phase`, `message`, `round`, and any extra keys (`findings_count`, `plan_items`, `next_round`, `max_rounds`, etc.).

Both are written by the same logger; use the file for audit and the terminal output for agent context.

## Prompts (copy-paste for each agent/session)

### 1. Identifier (Agent 1) — first run and every rerun after implement

**System/context:** You are the Identifier. Your job is to look at the provided image and list every part or region that causes it to seem clearly generated by AI. Be specific: name the region (e.g. "sky", "face", "hands", "fabric on left"), describe what looks AI (e.g. "over-smooth skin", "repetitive grass texture", "wrong finger count", "uncanny eyes"), and why it reads as AI. Output only the structured list, no preamble.

**User prompt:**

```
Look at the image I'm providing. Identify and list every part of the image that makes it look clearly AI-generated.

For each item provide:
- id: short id (e.g. "1", "2")
- region: where in the image (e.g. "upper left sky", "face", "hands", "foreground fabric")
- what: what looks AI (e.g. "over-smoothed skin", "repetitive texture", "anatomy error")
- why: one sentence on why it reads as AI

Output a JSON object with key "findings", value an array of objects with keys: id, region, what, why.

If nothing strongly suggests AI generation, use "findings": [].
```

**Output format (save as `findings.json`):**

```json
{
  "findings": [
    { "id": "1", "region": "face", "what": "over-smoothed skin, no pores", "why": "Uniform texture and lack of skin detail are common in generated images." },
    { "id": "2", "region": "hands", "what": "finger count or proportions off", "why": "Hands are often wrong in AI images." }
  ],
  "image_path": "assets/processing/ai-loop/current.png",
  "round": 1
}
```

---

### 2. Planner (Agent 2)

**System/context:** You are the Planner. You receive a list of findings (parts of an image that look AI-generated). Your job is to propose concrete changes that would make each part seem less AI-generated. Be specific: what to change (e.g. "add subtle skin texture", "fix hand anatomy", "break up repetitive pattern") and, if possible, how (e.g. "add noise", "inpaint with reference", "vary tile"). Output only the structured plan.

**User prompt:**

```
Here are the findings from the Identifier (parts of the image that look AI-generated):

[PASTE findings.json "findings" array or the file contents]

For each finding, propose what would make that part seem like it isn't AI. For each item provide:
- finding_id: same id from the findings
- change: concrete description of the change (e.g. "add subtle skin texture and pores")
- method: how to achieve it if you can (e.g. "add fine noise", "inpaint", "local contrast") or "manual edit"
- priority: "high" | "medium" | "low"

Output a JSON object with key "plan", value an array of objects with keys: finding_id, change, method, priority.
```

**Output format (save as `plan.json`):**

```json
{
  "plan": [
    { "finding_id": "1", "change": "Add subtle skin texture and pore detail", "method": "add fine noise or texture overlay", "priority": "high" },
    { "finding_id": "2", "change": "Correct hand anatomy and finger proportions", "method": "manual edit or inpaint with reference", "priority": "high" }
  ]
}
```

---

### 3. Reviewer (Agent 3)

**System/context:** You are the Reviewer. You receive the plan from the Planner. Your job is to review it and, for each proposed fix, write one clear yes/no question that the Identifier (who saw the original image) can answer: "Would [this specific fix] help reduce the AI look in [this specific part]?" Output only the list of questions in the structured form.

**User prompt:**

```
Here is the plan from the Planner:

[PASTE plan.json "plan" array or file contents]

For each plan item, write a single question we will ask the Identifier (who has seen the image): "Would [fix] help reduce the AI-generated look in [region]?" or similar. One question per plan item.

Output a JSON object with key "questions", value an array of objects with keys: finding_id, question.
```

**Output format (save as `review.json`):**

```json
{
  "questions": [
    { "finding_id": "1", "question": "Would adding subtle skin texture and pore detail to the face reduce the AI-generated look there?" },
    { "finding_id": "2", "question": "Would correcting the hand anatomy and finger proportions reduce the AI look in the hands?" }
  ]
}
```

---

### 4. Identifier — feedback (Agent 1 again)

**System/context:** You are the Identifier. You already listed what in the image looks AI-generated. Now we have a list of proposed fixes and questions. For each question, answer whether that fix would help (Yes / No / Partially) and one short reason. Output only the structured feedback.

**User prompt:**

```
You previously identified these parts of the image as looking AI-generated:

[PASTE findings.json "findings" array]

We have these proposed fixes and questions. For each question, answer whether that fix would help.

[PASTE review.json "questions" array]

Answer each with: answer (Yes | No | Partially), reason (one short sentence). Output a JSON object with key "feedback", value an array of objects with keys: finding_id, answer, reason.
```

**Output format (save as `feedback.json`):**

```json
{
  "feedback": [
    { "finding_id": "1", "answer": "Yes", "reason": "Skin texture is a major tell; adding it would help." },
    { "finding_id": "2", "answer": "Partially", "reason": "Fixing anatomy would help, but the lighting on the hand may still look off." }
  ]
}
```

---

### 5. Planner — improve plan (Agent 2 again)

**System/context:** You are the Planner. You have your original plan and the Identifier's feedback on each proposed fix. Produce an improved plan: keep or strengthen fixes that got Yes/Partially; drop or downgrade fixes that got No; add any refinement suggested by the feedback. Output only the improved plan.

**User prompt:**

```
Original plan:

[PASTE plan.json]

Identifier feedback on each fix:

[PASTE feedback.json]

Produce an improved plan. Keep or refine items that got Yes or Partially; drop or deprioritize items that got No; incorporate any refinement from the reasons. Same JSON shape: "plan" array with finding_id, change, method, priority. You may add optional "note" per item from feedback.
```

**Output format (save as `improved_plan.json`):**

```json
{
  "plan": [
    { "finding_id": "1", "change": "Add subtle skin texture and pore detail", "method": "add fine noise or texture overlay", "priority": "high" },
    { "finding_id": "2", "change": "Correct hand anatomy and fix lighting on hand", "method": "manual edit or inpaint", "priority": "high", "note": "Identifier said lighting may still look off; address both anatomy and lighting." }
  ]
}
```

---

### 6. Implementer

**Option A — Human:** Read `improved_plan.json` (or a generated `edit_spec.md`) and apply the edits in your image editor. Save the result as `assets/processing/ai-loop/edited_<N>.png` and set `current.png` to that image for the next round.

**Option B — Script/agent:** A script or agent reads `improved_plan.json` and either (1) generates `edit_spec.md` with step-by-step instructions for a human or external tool, or (2) calls an image-editing API (e.g. inpainting, local edits) if available. The result is saved as `edited_<N>.png` and copied to `current.png`.

---

### 7. Loop condition

After **Implement**:

1. Copy the new image to `assets/processing/ai-loop/current.png`.
2. Run **Identifier (Agent 1)** again on `current.png` (same prompt as in step 1).
3. Save the new output to `findings.json` (overwrite; use current `round` from `loop_state.json`).
4. If `findings` is empty or only low-severity items the user accepts as "good enough", **exit**: the loop is working.
5. If **round has reached max_rounds** (default 10), **exit**: no further rounds (see `loop_state.json` and `loop.log`).
6. Otherwise, run **Planner** on the new findings (step 2), then **Reviewer** (step 3), **Identifier feedback** (step 4), **Planner improve** (step 5), **Implement** (step 6), and repeat from step 1.

## CLI

From project root:

```bash
python -m stega.cli ai-loop init <image>    # Copy image to ai-loop/current.png; init loop_state (round 1, max 10); log to loop.log
python -m stega.cli ai-loop next            # Print which phase is next, round/max, and where to save output; log to loop.log
python -m stega.cli ai-loop implement       # Generate edit_spec.md; increment round; if round>10 set completed and stop; log to loop.log
```

All commands append to **`assets/processing/ai-loop/loop.log`** (JSONL). Check **`loop_state.json`** for current round and completed flag.

## One-shot "runner" usage

1. Put the image to process at `assets/processing/ai-loop/current.png` (or run `ai-loop init <image>`).
2. Invoke the **ai-detection-loop** skill (or run the Identifier prompt in this project with that image).
3. Save Identifier output to `assets/processing/ai-loop/findings.json`.
4. In a new session (or with Planner role): paste findings, run Planner prompt, save to `plan.json`.
5. In a new session (Reviewer): paste plan, run Reviewer prompt, save to `review.json`.
6. Back to Identifier session: paste findings + questions, run feedback prompt, save to `feedback.json`.
7. Back to Planner: paste plan + feedback, run improve prompt, save to `improved_plan.json`.
8. Implement: edit image per improved plan; save as `current.png`.
9. Rerun from step 2 (Identifier on new image). If findings are empty or acceptable, stop; else repeat steps 2–8.

---

## Skill integration

The **ai-detection-loop** skill triggers this workflow. When invoked:

- The agent creates `assets/processing/ai-loop/` if needed.
- The agent runs **Phase 1 (Identifier)**: it loads the user-provided image (or `current.png`), runs the Identifier prompt (by performing the analysis and outputting the structured findings), and writes `findings.json`.
- The agent then directs the user to run the next phases (Planner, Reviewer, Identifier feedback, Planner improve, Implement) or runs them in sequence if the user wants a single-session loop. After Implement, the agent reruns the Identifier on the new image and repeats until findings are empty or the user stops.
